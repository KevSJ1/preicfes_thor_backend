Primeros pasos

API REST para preparar a estudiantes para las pruebas ICFES: banco de preguntas, simulacros, aulas, intentos y resultados.

URL base

Todas las rutas de esta guía son relativas a:

http://localhost:3001/api/v1

Por ejemplo, POST /auth/login significa POST http://localhost:3001/api/v1/auth/login. El estado del servicio se consulta en GET /health (fuera de /api/v1).

Autenticación en 3 pasos

  1. Inicia sesión con POST /auth/login (correo y contraseña) o con el botón de Google (POST /auth/google, ver Iniciar sesión con Google). Recibes un accessToken (dura 15 minutos), un refreshToken (dura 30 días) y el user, que incluye su foto de perfil en fotoPerfilUrl.
  2. Envía el access token en cada petición protegida con la cabecera Authorization: Bearer <accessToken>.
  3. Cuando expire (respuesta 401), pide uno nuevo con POST /auth/refresh. Cada refresh devuelve un par de tokens nuevo; guarda siempre el último refresh token, el anterior deja de servir.
curl -X POST http://localhost:3001/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"correo":"profe@colegio.edu.co","contrasena":"mi-clave-segura"}'

curl http://localhost:3001/api/v1/auth/me \
  -H 'Authorization: Bearer eyJhbGciOi...'

Cabecera de institución

Profesores y gestores trabajan dentro de una institución. Para las operaciones institucionales (crear aulas, gestionar miembros, ver el progreso como gestor) envía también:

X-Institution-Id: 6f1c2a4e-....-....-....-............

La API comprueba que tengas una vinculación activa con esa institución; si no la tienes, la cabecera simplemente se ignora. Consulta tus instituciones con GET /users/me/institutions.

Cuentas nuevas: registrarse con POST /auth/register crea un usuario PENDIENTE con rol ESTUDIANTE. No podrá iniciar sesión hasta que un administrador lo active (y, si es profesor o gestor, le cambie el rol) con PATCH /users/:id. Lo mismo ocurre la primera vez que alguien entra con Google con un correo que no estaba registrado.

Foto de perfil

El login, el refresh y GET /auth/me devuelven fotoPerfilUrl: la URL de la imagen de perfil del usuario, o null si no tiene (muestra un avatar con sus iniciales). Cada usuario la cambia con PATCH /users/me enviando una URL http(s), normalmente la de una imagen ya subida a tu almacenamiento. Quienes entran con Google reciben su foto de Google si aún no tenían una.

Formato de respuestas y errores

Todas las respuestas son JSON. Una respuesta exitosa siempre envuelve el resultado en data:

{ "data": { "id": "…", "nombre": "Aula 11A" } }

Un error siempre tiene esta forma (details aparece solo cuando ayuda, por ejemplo en validaciones):

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Datos de aula inválidos",
    "details": { "fieldErrors": { "nombre": ["Required"] } }
  }
}

Reglas generales

  • Identificadores: todos los IDs son UUID. Un ID con formato inválido en la ruta responde 400.
  • Campos extra: los cuerpos de escritura rechazan campos desconocidos (400). El servidor asigna IDs, autor, fechas y totales; no los envíes.
  • Fechas: formato ISO 8601 con zona horaria, p. ej. 2026-10-20T07:00:00-05:00.
  • Listas: parámetro ?limit= (por defecto 50, máximo 100). Algunas listas aceptan ?offset=.
  • Actualizaciones (PATCH): envía solo los campos que quieres cambiar.
  • Límite de peticiones: 300 cada 15 minutos por IP; 20 cada 15 minutos en login (con contraseña o con Google), registro, refresh, cambio de contraseña y solicitud institucional. Al superarlo recibes 429.

Roles y permisos

RolPuede…
ADMINISTRADORTodo: activar usuarios y asignar roles, catálogos ICFES, instituciones y solicitudes, auditoría.
GESTOR_INSTITUCIONALCon X-Institution-Id: vincular profesores, ver aulas, resultados y progreso de su institución, editar datos de la institución.
PROFESORCrear preguntas, estímulos, plantillas y cuestionarios; crear aulas, invitar estudiantes, asignar cuestionarios y revisar resultados.
ESTUDIANTEUnirse a aulas con un código, presentar cuestionarios (libres o asignados) y ver sus resultados.

En cada endpoint, la etiqueta de la derecha indica qué roles pueden usarlo. «Autenticado» significa cualquier usuario con sesión iniciada.

Flujos típicos

Poner en marcha una institución (administrador)

  1. Revisa las solicitudes con GET /institution-requests y apruébala con PATCH /institution-requests/:id/review ("estado": "APROBADA"). Esto crea la institución. También puedes crearla directo con POST /institutions.
  2. Activa a los usuarios registrados y asígnales rol con PATCH /users/:id.
  3. Vincula al gestor con POST /institutions/:id/members ("rol": "GESTOR_INSTITUCIONAL"). El gestor podrá vincular a sus profesores.

Crear y asignar un simulacro (profesor)

  1. (Opcional) Registra imágenes con POST /media y textos base con POST /stimuli; publícalos.
  2. Crea preguntas con POST /questions (o en lote con POST /questions/import) y publícalas con POST /questions/:versionId/publish.
  3. Elige o crea una plantilla (GET/POST /templates) y crea el cuestionario con POST /questionnaires.
  4. Agrega sesiones (POST /questionnaires/:id/sessions) e ítems (…/sessions/:sessionId/items) y publícalo con POST /questionnaires/:id/publish.
  5. Crea un aula con POST /classrooms (con X-Institution-Id), genera un código con POST /classrooms/:id/invitations y compártelo.
  6. Asigna el cuestionario con POST /classrooms/:id/assignments y consulta resultados con GET /classrooms/:id/results y GET /attempts/:id/review.

Presentar un simulacro (estudiante)

  1. Únete al aula con POST /classrooms/enroll y el código del profesor.
  2. Mira tus asignaciones con GET /classrooms/mine.
  3. Inicia el intento con POST /attempts/assignments/:assignmentId y carga las preguntas con GET /attempts/:id.
  4. Guarda cada respuesta con PUT /attempts/:id/answers/:itemId (puedes cambiarla mientras el intento esté en progreso).
  5. Entrega con POST /attempts/:id/finish y consulta tu puntaje con GET /attempts/:id/result.

Iniciar sesión con Google

La API acepta el ID token que entrega el botón oficial «Iniciar sesión con Google» (Google Identity Services), lo verifica con Google y responde igual que POST /auth/login. El frontend nunca maneja contraseñas de Google.

Configuración (una sola vez)

  1. En Google Cloud Console → APIs y servicios → Credenciales, crea un ID de cliente OAuth de tipo Aplicación web.
  2. En Orígenes de JavaScript autorizados agrega la URL del frontend (por ejemplo http://localhost:5173 y el dominio de producción). No hace falta URI de redirección.
  3. Copia el ID de cliente (…apps.googleusercontent.com) en la variable GOOGLE_CLIENT_ID del servidor y reinícialo. Sin esa variable, POST /auth/google responde 503 GOOGLE_NOT_CONFIGURED.
  4. Si la base de datos se creó antes de esta función, aplica una vez SQL/migrations/001_perfil_y_google.sql, que agrega las columnas de foto y Google a usuario. Puedes ejecutarlo varias veces sin problema.

El botón en el frontend

Pregunta a GET /auth/providers si Google está habilitado y con qué clientId; así el frontend no necesita tener el ID escrito en el código.

<script src="https://accounts.google.com/gsi/client" async></script>
<div id="boton-google"></div>

<script type="module">
const API = 'http://localhost:3001/api/v1';
const { data } = await (await fetch(`${API}/auth/providers`)).json();

if (data.google.habilitado) {
  google.accounts.id.initialize({
    client_id: data.google.clientId,
    callback: async ({ credential }) => {
      const res = await fetch(`${API}/auth/google`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ idToken: credential }),
      });
      const body = await res.json();
      if (res.status === 200) guardarSesion(body.data);           // accessToken, refreshToken, user (con fotoPerfilUrl)
      else if (res.status === 201) avisar('Cuenta creada; un administrador debe activarla.');
      else avisar(body.error.message);                           // 403 ACCOUNT_NOT_ACTIVE, 401, 409…
    },
  });
  google.accounts.id.renderButton(document.getElementById('boton-google'),
    { theme: 'outline', size: 'large', text: 'signin_with', locale: 'es' });
}
</script>

En React, Vue o Angular el flujo es el mismo: carga el script de Google, renderiza el botón y envía el credential a POST /auth/google. Si el frontend usa una CSP, permite https://accounts.google.com en script-src, frame-src y connect-src.

Qué pasa con cada cuenta

SituaciónRespuesta
Correo nunca registrado201: se crea una cuenta ESTUDIANTE PENDIENTE con la foto de Google. Como en el registro normal, un administrador debe activarla.
Cuenta existente con el mismo correo (registrada con contraseña)Se vincula a Google automáticamente; luego puede entrar con cualquiera de los dos métodos. Su foto propia se conserva.
Cuenta vinculada y ACTIVO200 con accessToken, refreshToken y user, igual que el login.
Cuenta PENDIENTE, BLOQUEADO o INACTIVO403 ACCOUNT_NOT_ACTIVE con details.estado.
El correo ya está vinculado a otra cuenta de Google409 GOOGLE_ACCOUNT_MISMATCH.
Las cuentas creadas con Google no tienen contraseña: no pueden usar POST /auth/login ni POST /auth/change-password (409 PASSWORD_NOT_SET). Después del login con Google, el refresh y el logout funcionan igual que siempre.

Probar con Postman

El repositorio incluye una colección que recorre toda la API con pruebas automáticas en cada petición: registro, sesiones, foto de perfil, Google, institución, catálogos, contenido, cuestionario, aula, intento, calificación y auditoría.

  1. Importa en Postman postman/PreICFES-Thor.postman_collection.json y el entorno postman/PreICFES-Thor.local.postman_environment.json.
  2. En el entorno define baseUrl (por ejemplo http://localhost:3001), y adminEmail y adminPassword de un administrador activo (se crea con npm run create-admin).
  3. Ejecuta la colección completa con el Collection Runner, en orden: cada petición guarda en variables los IDs que usan las siguientes.
npx newman run postman/PreICFES-Thor.postman_collection.json \
  -e postman/PreICFES-Thor.local.postman_environment.json --env-var adminPassword='…'
Crea datos reales (usuarios, una institución, preguntas…): úsala en una base de desarrollo, nunca en producción. Cada corrida usa un sufijo propio, así que puede repetirse. Una corrida consume 17 de las 20 peticiones permitidas cada 15 minutos en login y registro: espera entre corridas o levanta la API con NODE_ENV=test, que desactiva ese límite. La petición de Google acepta 503 si el servidor no tiene GOOGLE_CLIENT_ID y 401 si lo tiene.

Autenticación

POST/auth/registerPúblico

Crea una cuenta en estado PENDIENTE con rol ESTUDIANTE. Un administrador debe activarla.

{ "nombres": "Ana", "apellidos": "Pérez", "correo": "ana@correo.com", "contrasena": "minimo-8-caracteres" }
  • Respuesta 201: { id, estado: "PENDIENTE", mensaje }.
  • 409 CONFLICT si el correo ya está registrado.
POST/auth/loginPúblico

Inicia sesión. Solo funciona con cuentas ACTIVO.

{ "correo": "ana@correo.com", "contrasena": "minimo-8-caracteres" }
Respuesta
{ "data": {
  "accessToken": "eyJ…", "refreshToken": "eyJ…",
  "user": { "id": "…", "nombres": "Ana", "apellidos": "Pérez", "correo": "ana@correo.com",
            "fotoPerfilUrl": "https://cdn.ejemplo.com/ana.png", "rol": "ESTUDIANTE" }
} }

fotoPerfilUrl es la imagen de perfil del usuario (o null si no tiene). Se carga con PATCH /users/me o se toma de Google la primera vez que entra con Google.

GET/auth/providersPúblico

Métodos de inicio de sesión disponibles. Úsalo para decidir si mostrar el botón de Google y con qué ID de cliente.

{ "data": { "contrasena": true, "google": { "habilitado": true, "clientId": "1234-abc.apps.googleusercontent.com" } } }
POST/auth/googlePúblico

Inicia sesión con el ID token (credential) que entrega el botón de Google. Ver Iniciar sesión con Google.

{ "idToken": "eyJhbGciOiJSUzI1NiIs…" }
  • 200: misma respuesta que /auth/login.
  • 201: { id, estado: "PENDIENTE", mensaje } si se creó una cuenta nueva (requiere activación).
  • 401 INVALID_GOOGLE_TOKEN, 403 ACCOUNT_NOT_ACTIVE, 409 GOOGLE_ACCOUNT_MISMATCH, 503 GOOGLE_NOT_CONFIGURED.
POST/auth/refreshPúblico

Cambia un refresh token por un par nuevo (misma forma que el login). El refresh token usado queda invalidado.

{ "refreshToken": "eyJ…" }
Importante: si se reutiliza un refresh token ya usado, la API asume que fue robado y cierra todas las sesiones del usuario. Guarda siempre el último token recibido.
POST/auth/logoutPúblico

Cierra la sesión revocando el refresh token. Responde 204 sin cuerpo.

{ "refreshToken": "eyJ…" }
GET/auth/meAutenticado

Devuelve el usuario actual: id, nombres, apellidos, correo, fotoPerfilUrl, rol, y si envías X-Institution-Id válido, también rolInstitucional e idInstitucion.

POST/auth/change-passwordAutenticado

Cambia la contraseña. Cierra todas las sesiones de refresco (habrá que volver a iniciar sesión en otros dispositivos). Responde 204.

{ "contrasenaActual": "clave-vieja", "contrasenaNueva": "clave-nueva-segura" }
  • 409 PASSWORD_NOT_SET si la cuenta se creó con Google y no tiene contraseña.

Usuarios

GET/users/me/institutionsAutenticado

Instituciones a las que estás vinculado, con tu rol en cada una y el estado de la vinculación. Úsalo para obtener el valor de X-Institution-Id.

PATCH/users/meAutenticado

Actualiza tu propio perfil: nombre y foto. Envía uno o más campos. La foto es una URL http(s) (por ejemplo la url de un recurso registrado con POST /media); null la quita.

{ "nombres": "Ana María", "fotoPerfilUrl": "https://cdn.ejemplo.com/ana.png" }
  • Respuesta 200: tu usuario actualizado, con fotoPerfilUrl y vinculadoGoogle.
  • El rol y el estado no se cambian aquí; eso lo hace un administrador.
GET/usersAdministrador

Lista de usuarios. Filtros opcionales: ?q= (nombre o correo), ?estado=PENDIENTE|ACTIVO|BLOQUEADO|INACTIVO, ?rol=, ?limit=, ?offset=.

GET/users/:idAdministrador

Detalle de un usuario (con fotoPerfilUrl y vinculadoGoogle), incluyendo sus vinculaciones institucionales.

PATCH/users/:idAdministrador

Activa, bloquea o cambia el rol de una cuenta. Envía uno o más campos.

{ "estado": "ACTIVO", "rol": "PROFESOR", "correoVerificado": true }
  • Roles: ADMINISTRADOR, GESTOR_INSTITUCIONAL, PROFESOR, ESTUDIANTE.
  • Desactivar o cambiar el rol cierra las sesiones del usuario.
  • 409 SELF_LOCKOUT: no puedes desactivarte ni quitarte el rol de administrador.

Catálogos ICFES

Datos de referencia para clasificar preguntas. Siguen la estructura del ICFES:

  • Prueba → competencia → afirmación → evidencia → tarea (se asocia a la pregunta con tareaId).
  • Prueba → componente → tema (se asocian a la pregunta con temas).
GET/catalogsPúblico

Devuelve en una sola llamada las listas base: pruebas, tiposPregunta, dificultades, modalidades y servicios. Aquí obtienes los IDs para crear preguntas y plantillas.

GET/catalogs/{nivelPadre}/:id/{nivel}Público

Hijos de un elemento del catálogo. Solo activos; agrega ?incluirInactivos=true para ver todos. Rutas disponibles:

  • /catalogs/pruebas/:id/competencias
  • /catalogs/competencias/:id/afirmaciones
  • /catalogs/afirmaciones/:id/evidencias
  • /catalogs/evidencias/:id/tareas
  • /catalogs/pruebas/:id/componentes
  • /catalogs/componentes/:id/temas
POST/catalogs/{nivelPadre}/:id/{nivel}Administrador

Crea un elemento bajo su padre (mismas rutas que el GET). Campos según el nivel:

NivelCuerpo
competencias{ "codigo", "nombre", "descripcion"? }
afirmaciones, evidencias, tareas{ "codigo", "descripcion" }
componentes, temas{ "nombre", "descripcion"? }
POST /catalogs/pruebas/08286be2-3c42-4891-b0b4-66242f37e46a/componentes
{ "nombre": "Álgebra y cálculo" }
PATCH/catalogs/{nivel}/:idAdministrador

Edita o desactiva un elemento: /catalogs/competencias/:id, /afirmaciones/:id, /evidencias/:id, /tareas/:id, /componentes/:id, /temas/:id. Acepta los mismos campos del POST más "activo": false.

Solicitudes institucionales

Formulario público para que un colegio pida acceso a la plataforma.

POST/institution-requestsPúblico
{
  "nombreInstitucion": "Colegio San José",
  "nombreResponsable": "María Gómez",
  "cargo": "Rectora",
  "correoInstitucional": "rectoria@sanjose.edu.co",
  "telefono": "3001234567",
  "ciudad": "Montería",
  "rangoEstudiantes": "100-500",
  "mensaje": "Queremos usar los simulacros con grado 11.",
  "aceptaPoliticaDatos": true,
  "servicios": ["a0000000-0000-4000-8000-000000000002"]
}
  • aceptaPoliticaDatos debe ser true. Los IDs de servicios salen de GET /catalogs.
  • Respuesta 201: { id, estado: "PENDIENTE", fechaCreacion }.
GET/institution-requestsAdministrador

Lista de solicitudes, filtrable con ?estado=PENDIENTE|EN_REVISION|CONTACTADA|APROBADA|RECHAZADA.

GET/institution-requests/:idAdministrador

Detalle de una solicitud, incluidos los servicios pedidos y las notas internas.

PATCH/institution-requests/:id/reviewAdministrador

Cambia el estado de la solicitud. Al aprobarla se crea la institución automáticamente y su ID vuelve en institucionId.

{ "estado": "APROBADA", "notasInternas": "Llamada realizada el lunes" }
  • Estados: EN_REVISION, CONTACTADA, RECHAZADA, APROBADA.
  • 409 INVALID_STATE: una solicitud aprobada ya no puede cambiar de estado.

Instituciones

GET/institutionsAutenticado

Instituciones donde tienes vinculación activa (el administrador ve todas).

POST/institutionsAdministrador

Crea una institución directamente, sin solicitud previa.

{ "nombre": "Colegio San José", "nit": "900123456-7", "correo": "info@sanjose.edu.co",
  "telefono": "6047000000", "direccion": "Calle 1 # 2-3", "ciudad": "Montería", "logoUrl": "https://…/logo.png" }

Solo nombre es obligatorio.

GET/institutions/:idMiembro activo · Administrador

Datos de la institución y tu rol en ella.

PATCH/institutions/:idAdministrador · Gestor de la institución

Actualiza datos (mismos campos que el POST). Enviar un campo como null lo vacía. Solo el administrador puede cambiar "estado": "ACTIVA|INACTIVA|BLOQUEADA". El gestor debe enviar X-Institution-Id.

GET/institutions/:id/progressMiembro activo · Administrador

Resumen por aula: estudiantes evaluados, intentos finalizados, promedio (%) y fecha del último intento. Administrador y gestor ven todas las aulas; un profesor solo las suyas.

GET/institutions/:id/membersAdministrador · Gestor

Profesores y gestores vinculados, con el estado de su vinculación.

POST/institutions/:id/membersAdministrador · Gestor

Vincula a un usuario existente (o reactiva su vinculación) usando su correo.

{ "correo": "profe@colegio.edu.co", "rol": "PROFESOR" }
  • El usuario ya debe tener ese rol global (lo asigna un administrador). Si no, responde 400 ROLE_MISMATCH.
  • Un gestor solo puede vincular PROFESOR; los gestores los vincula el administrador.
  • 404 USER_NOT_FOUND si no existe una cuenta con ese correo.
PATCH/institutions/:id/members/:memberIdAdministrador · Gestor

Cambia el estado de una vinculación. memberId es el id que devuelve la lista de miembros.

{ "estado": "RETIRADA" }

Estados: ACTIVA, INACTIVA, RETIRADA. Un gestor solo puede modificar profesores.

Recursos multimedia y fuentes

La API guarda solo los metadatos del archivo; el archivo debe estar subido en un almacenamiento externo que proporcione la URL.

GET/mediaAdministrador · Profesor

Tus recursos (el administrador ve todos). Filtro opcional ?tipo=IMAGEN|AUDIO|VIDEO|DOCUMENTO.

POST/mediaAdministrador · Profesor
{ "tipo": "IMAGEN", "url": "https://cdn.ejemplo.com/grafica.png", "nombreArchivo": "grafica.png",
  "mimeType": "image/png", "textoAlternativo": "Gráfica de barras de ventas", "tamanoBytes": 48213 }

El mimeType debe corresponder al tipo (image/*, audio/*, video/*, o application/*/text/* para documentos). Usa el id devuelto en recursos de preguntas y estímulos.

GET/media/:idAdministrador · Profesor

Detalle de un recurso propio.

DELETE/media/:idAdministrador · Profesor

Elimina un recurso propio. Si está en uso en alguna pregunta, estímulo u opción responde 409 RESOURCE_IN_USE.

GET/media/sourcesAdministrador · Profesor

Fuentes de contenido (de dónde sale una pregunta o texto). Búsqueda con ?q=.

POST/media/sourcesAdministrador · Profesor
{ "nombre": "Cuadernillo ICFES 2023", "tipo": "ICFES", "referencia": "Saber 11, sesión 1", "anio": 2023 }

Tipos: PROPIA, ICFES, LIBRO, OTRO. El id se usa como fuenteId.

Estímulos

Un estímulo es el material de contexto que comparten varias preguntas: un texto de lectura, una tabla, una situación. Tiene versiones; cada versión pasa por BORRADOR → PUBLICADA → ARCHIVADA.

Las rutas con :id usan el ID de la versión, excepto POST /stimuli/:id/versions, que usa el ID del estímulo (estimuloId).
GET/stimuliAdministrador · Profesor · Gestor

Lista versiones publicadas y las tuyas. Filtros: ?q= (título o código), ?estado=.

POST/stimuliAdministrador · Profesor

Crea el estímulo con su versión 1 en borrador.

{ "titulo": "El viaje en tren", "contenido": "Un tren sale de Bogotá a las 8:00…",

Preguntas

Las preguntas también son versionadas: preguntaId identifica la pregunta y versionId (o id) cada versión. Editar una pregunta = crear una versión nueva.

Las rutas con :id usan el ID de la versión, excepto POST /questions/:id/versions, que usa el preguntaId.

Intentos

Un intento es la presentación de un cuestionario por un estudiante. Puede ser libre (práctica con cualquier cuestionario publicado) o asignado (desde una asignación del aula).

Tiempo límite: cada intento tiene una fechaLimite = hora de inicio + suma de la duración de las sesiones (con 1 minuto de margen). Pasado ese límite, o si la asignación se cierra, el intento pasa a VENCIDO. Las respuestas ya guardadas sí cuentan para el puntaje.
Estados: EN_PROGRESO, FINALIZADO, VENCIDO.

Inicia un intento de práctica libre.

{ "cuestionarioId": "id-cuestionario" }
POST/attempts/assignments/:assignmentIdEstudiante

Inicia un intento de una asignación de tu aula. Sin cuerpo.

  • 409 ATTEMPT_IN_PROGRESS: ya tienes uno abierto; su ID viene en error.details.intentoId para continuarlo.
  • 409 ATTEMPTS_EXHAUSTED: usaste todos los intentos permitidos.
  • 403 ASSIGNMENT_CLOSED: la asignación aún no abre o ya cerró.
